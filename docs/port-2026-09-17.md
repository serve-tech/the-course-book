## Database baseline

`supabase/migrations/20260917142631_port_existing_course_book.sql` records the applied schema migration. Live comparison confirmed matching table/column definitions, constraints, indexes, policies, grants, signup trigger, and application function. Default schema privileges also matched. Data exports and credentials are intentionally excluded from this repository.

A transaction that was fully rolled back verified the signup-to-profile trigger, own-user round creation and ranking updates, cross-user round insertion rejection, anonymous course/ranking access, and private round visibility. Referential-integrity checks found no orphan application records.

This port preserves the original access model, including the existing administrative import/backup tables and member profile visibility. Security advisor findings match the source: RLS is disabled on two auxiliary tables, pg_trgm is in public, the signup trigger function has broad execute grants, and leaked-password protection is disabled. These inherited findings are recorded for follow-up; this port does not constitute a security redesign.

## Authentication and email

The new Auth Site URL and allowed confirmation redirect both point to the new GitHub Pages address. Email confirmation and password policies were retained, and email templates were copied with updated project/site links. Project signing keys are independent.

Custom Resend SMTP is configured using the actual API key supplied by the owner, with the original host, port, username, and sender settings. Configuration read-back confirmed the settings and a configured password; a secure SMTP login to Resend succeeded. No email was sent, so inbox delivery has not been tested.

Supabase's configuration API returns an opaque password fingerprint, not the usable credential. The source fingerprint was not reused. The actual credential exists only in the destination service configuration, not in this repository or browser code. The email-provider account remains shared with the original app until a separate credential/account is configured.

## Frontend and release

The actual `index.html` and original Git history are in the new repository. Its project URL, publishable key, and authentication redirect target the new project/site. GitHub Pages publishes `main` from the repository root, with `.nojekyll`.

Published HTTP/API checks succeeded for the page, course catalog, ranking data, and Auth settings. Anonymous browser smoke testing loaded the World, USA All, and USA Public lists (100 rows each), and opened the sign-in dialog without JavaScript or network errors.

A user-reported inherited sign-in bug was identified: the visible email was validated but the hidden signup email was submitted. Commit `cd2864d` corrects the field mapping. Four Node regression tests cover empty/stale hidden signup fields, invalid sign-in input, and the unchanged signup email flow.

React, Render, and broader application refactoring are deferred until after this ownership migration.
